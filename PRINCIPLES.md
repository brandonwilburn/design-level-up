# Principles — Design Depth

> The next tier above the brand-wide design language. This is what
> the design language becomes when you stop thinking about *layout*
> and start thinking about *composition*. The brand-wide language
> (see `wiki/clusters/cross-cluster/concepts/design-language/`) is
> the floor; this is the ceiling that any new design work should
> reach for.

## Why this exists

The brand-wide design language captures **restraint**: one accent,
lean motion, section grammar, font pair, single-accent restraint.
Restraint is what makes a site not bad. It is not what makes a
site *good*.

What makes a site look genuinely designed — and not generated by a
model trained on Tailwind examples — is a different set of
capabilities, most of which the current language does not touch:

- Asymmetric editorial layout (12-col main + 4-col sidebar; not
  "everything 12-col equal")
- Typographic depth (variable fonts with optical-size axes,
  oldstyle numerals, real small caps, real scale with intent)
- Layout detail (pull quotes, marginalia, drop caps, hanging
  punctuation, real captions with photo credits)
- Custom detail (a hand-drawn map, a custom divider, an actual SVG
  illustration — something a person made)
- Imagery with intent (when full-bleed, when tight crop, when
  illustration, when no image at all as a designed choice)
- Material (when a hairline border beats a shadow; when a subtle
  paper-grain texture earns its place)
- Voice in copy (specificity test: every claim has a number, a
  name, or a detail)

This document is the canonical reference for all seven. The
**Yard & Larder** reference implementation under `reference/` is
the proof that the bar is achievable. It is a single page, no
framework, no build step — open `reference/index.html` in a
browser.

## 1. Asymmetric editorial layout

### The AI default

Every section is a 12-col grid. Content is centered, or pinned to
the left with a symmetric right column. Hero is full-bleed image
with overlaid centered text. Every card has the same weight. Every
column is the same width. The page reads as "uniform" because the
model defaulted to the safe choice: equal-weight, centered,
symmetric.

### The principle

A designed page has a **dominant column** and a **secondary
column**. Most of the work happens in the dominant column (8 of
12, or 9 of 12, or 7 of 10). The secondary column carries:
asides, marginalia, related content, captions, the small
specifics. Sometimes a third micro-column carries labels,
captions, or a callout. The grid is mixed; the rhythm is
intentional.

This is editorial layout, the kind magazines and feature
newspapers have used for a century. It is not new. It is just
uncommon in 2026 web design because AI defaults to the symmetric,
equal-weight page.

### The pattern

```html
<!-- Dominant + secondary, NOT two equal halves -->
<article class="prose">
  <p class="lead">...main copy in 8 of 12 cols...</p>
  <p>...continues in 8 of 12 cols...</p>
  <aside class="margin-note">...aside in 4 of 12 cols, aligned
    to the right margin of the dominant column...</aside>
  <p>...continues...</p>
</article>
```

```css
.prose {
  display: grid;
  grid-template-columns: minmax(0, 8fr) minmax(0, 4fr);
  gap: clamp(1.5rem, 4vw, 4rem);
  max-width: 64rem;
}
.prose > p { grid-column: 1; }
.prose > .margin-note { grid-column: 2; align-self: start; }
```

### Specificity test

- Does the page have a clear dominant column? If every section is
  two equal halves, you have not designed it.
- Is at least one piece of content running in a different
  column-width than the rest? (An aside, a pull quote, a figure
  that breaks the column.)
- Is the hero asymmetric? If the hero is centered, you have
  defaulted to the AI baseline.

## 2. Typographic depth

### The AI default

The model picks Inter (or a system sans), uses a 1.25 modular
scale, sets `font-weight: 700` for headings, and never opens
OpenType features. Numerals are lining by default. There are no
small caps. There is no difference between display and body
settings — the same Inter at the same weight is used for both.

### The principle

Designed typography is **layered**, not uniform. At minimum:

1. **Variable font with optical-size axis.** Display sizes (>= 24px)
   and body sizes (< 24px) want different optical settings. A
   variable font with an `opsz` axis (Fraunces, Source Serif,
   Newsreader, Roboto Flex) gives you this for free.

2. **Oldstyle numerals** in running text, lining numerals in tabular
   data. OpenType feature `onum` enables oldstyle. Cart totals,
   prices, and tabular lists use lining (the default).

3. **Real small caps** for eyebrows, captions, and labels. OpenType
   `smcp` enables them. Real small caps look like refined
   capitals; tracked uppercase looks like SHOUTING.

4. **A scale with intent.** The 1.25 default is the AI default.
   1.333 (perfect fourth) or 1.414 (augmented fourth) or 1.5
   (perfect fifth) are designed choices. Pick one and apply it
   consistently — to the body, to the heading, to the eyebrow.

5. **Display settings vs body settings.** The display face may
   have tighter tracking and slightly tighter leading at large
   sizes. The body face has more open tracking and looser
   leading. These are not the same setting.

6. **Numeral alignment.** `font-variant-numeric: tabular-nums` for
   cart totals. Default (proportional) for editorial running text.

### The pattern

```css
:root {
  /* Variable display serif with optical-size axis.
     Fraunces is free on Google Fonts. */
  --font-display: "Fraunces", "Cormorant Garamond",
                  "Playfair Display", Georgia, serif;
  --font-body:    -apple-system, BlinkMacSystemFont, "Inter",
                  "Segoe UI", Roboto, "Helvetica Neue", Arial,
                  sans-serif;

  /* 1.333 modular scale — designed, not the AI 1.25. */
  --t-base:  1.0625rem;   /* 17px */
  --t-sm:    calc(var(--t-base) * 0.875);
  --t-lg:    calc(var(--t-base) * 1.333);
  --t-xl:    calc(var(--t-base) * 1.333 * 1.333);
  --t-2xl:   calc(var(--t-base) * 1.333 * 1.333 * 1.333);
  --t-3xl:   calc(var(--t-base) * 1.333 * 1.333 * 1.333 * 1.333);
}

body {
  font-family: var(--font-body);
  font-size: var(--t-base);
  line-height: 1.6;
  font-feature-settings: "kern" 1, "liga" 1, "calt" 1;
}

.display {
  font-family: var(--font-display);
  font-variation-settings: "opsz" 144, "SOFT" 50;
  font-size: var(--t-3xl);
  line-height: 1.05;
  letter-spacing: -0.015em;
  font-weight: 500;
}

.eyebrow {
  font-family: var(--font-body);
  font-feature-settings: "smcp" 1, "c2sc" 1;
  text-transform: lowercase;     /* small caps already exist;
                                    lowercase is the typographic
                                    convention for smcp */
  letter-spacing: 0.18em;
  font-size: var(--t-sm);
  color: var(--c-accent);
}

.prose-numerals {
  font-variant-numeric: oldstyle-nums proportional-nums;
  font-feature-settings: "onum" 1, "kern" 1;
}

.tabular {
  font-variant-numeric: lining-nums tabular-nums;
}
```

### Specificity test

- Is the display face a variable font with an `opsz` axis? (If
  not, you have not leveled up.)
- Are running-text numerals oldstyle? (Look at the digits in a
  paragraph of body copy. If they are all the same height as
  capitals, they are lining — AI default.)
- Are eyebrows real small caps (OpenType `smcp`) or tracked
  uppercase? (Tracked uppercase is the AI default.)
- Is the modular scale 1.25 (AI) or something with intent?

## 3. Layout detail

### The AI default

The model puts text in a column. Sometimes the column is centered.
Sometimes it has a max-width. There are no asides, no marginalia,
no pull quotes, no drop caps, no hanging punctuation, no captions
with photo credits. The body of the page reads as a single
rhythm: paragraph, paragraph, paragraph, done.

### The principle

Designed prose has **rhythm within the column**. The same column
of text supports a drop cap, a paragraph break that aligns to a
baseline, a pull quote that breaks out, a margin note in the
secondary column, a hanging punct that sits in the margin, a
figure with a real caption and a real credit. These are the
tools a copy editor or art director uses to give a long text
*shape*.

The most underused tool is the **drop cap**. A real drop cap is
the first letter of a paragraph, sized 3-5 lines tall, sitting
flush with the cap-height of the surrounding body text. It is
not a CSS hack. It is a typographic device that has been in
books since the 12th century. The page that uses it reads as
"designed" because no AI default ever produces one.

### The pattern

```css
/* Drop cap: real, sized to 3 lines of body text, baseline-aligned */
.prose > p:first-of-type::first-letter {
  font-family: var(--font-display);
  font-variation-settings: "opsz" 144;
  font-size: 4.5em;
  font-weight: 500;
  float: left;
  line-height: 0.85;
  margin: 0.05em 0.08em -0.05em -0.04em;
  color: var(--c-accent);
}

/* Pull quote: breaks out of the column, asymmetric */
.pullquote {
  font-family: var(--font-display);
  font-variation-settings: "opsz" 144;
  font-size: var(--t-xl);
  line-height: 1.15;
  font-weight: 400;
  font-style: italic;
  margin: 2rem 0;
  padding-left: 1.5rem;
  border-left: 1px solid var(--c-line);
  color: var(--c-text);
}
.pullquote cite {
  display: block;
  font-family: var(--font-body);
  font-style: normal;
  font-size: var(--t-sm);
  letter-spacing: 0.06em;
  color: var(--c-text-mute);
  margin-top: 0.5rem;
}

/* Margin note: lives in the secondary column */
.margin-note {
  font-size: var(--t-sm);
  color: var(--c-text-mute);
  line-height: 1.5;
}
.margin-note::before {
  content: "— ";
  color: var(--c-accent);
}

/* Hanging punctuation: the opening quote sits in the margin */
.hang-punct {
  hanging-punctuation: first last;
}
```

```html
<article class="prose hang-punct">
  <p>The first paragraph. The drop cap on the first letter
    carries 3 lines of body text. The remaining text wraps
    cleanly around it. Real drop caps have a baseline alignment;
    the cap-height of the drop letter should sit at the cap-height
    of the surrounding body text.</p>

  <aside class="margin-note">
    This aside lives in the 4-col secondary column. It carries
    a one-line fact that supports the main copy without
    breaking its flow.
  </aside>

  <p>Continuation of the main copy. Nothing has changed in
    width; the aside floated into the secondary column and the
    body kept flowing at its natural width.</p>

  <blockquote class="pullquote">
    If it isn't something we'd hand a friend, it doesn't make
    the shelf.
    <cite>— Sarah, on opening day</cite>
  </blockquote>

  <p>The pull quote breaks the rhythm of the column. It sits
    indented from the left margin with a hairline border. The
    citation sits below in small caps.</p>
</article>
```

### Specificity test

- Is there at least one drop cap on the page? (If not, the
  long-form copy is not designed.)
- Is there at least one margin note in a secondary column?
  (If not, the layout is single-column.)
- Are there pull quotes? Are they broken out of the column or
  inline?
- Do figures have real captions with credits? (Not "Photo by
  staff" — a real name, a real date, a real source.)

## 4. Imagery with intent

### The AI default

The model picks a stock photo (Unsplash, Pexels), drops it in a
hero, possibly adds a gradient overlay, possibly puts a card on
top with rounded corners. The same approach is repeated for the
"about" image, the "team" image, the "product" image. Every
image is a stock photo. The page reads as "assembled" because it
was.

### The principle

Imagery is a **decision**, not a slot to fill. The choices:

- **Full-bleed photograph.** Earned. Used for the hero or one
  signature moment per page. The image has to be specific to
  the merchant (their food, their space, their maker) — not
  generic.
- **Tight crop, specific subject.** A macro of a hand pouring
  wax. A closeup of a label, showing the texture. The image
  carries information at this scale.
- **Illustration or iconography, hand-drawn.** A simple SVG of
  the storefront. A custom divider. A hand-drawn map. These
  are *made*, not licensed. They read as "this was designed."
- **No image, by design.** A section that is all type. A
  divider that is just a hairline. The absence of an image is
  a choice, not a default.

### The pattern

- If a section is "all type," justify it: the type carries the
  meaning; an image would dilute it.
- If a section uses a full-bleed photo, the photo has to be
  specific to the merchant. Generic stock = the page reads as
  generic.
- Custom SVG illustrations earn their place when they tell the
  reader something they would not have known. (A custom map
  of Bardstown with the shop marked tells the reader "we are
  here, you can walk here." Stock photography does not.)

### Specificity test

- Is at least one piece of imagery on the page specific to the
  merchant? (Not stock. A real photo of their space, their
  product, their people.)
- Is at least one section image-free by design? (A page with
  images in every section has not been edited.)
- Is there at least one *made* element — a hand-drawn map, a
  custom SVG, a real illustration? (If everything is licensed,
  nothing was designed.)

## 5. Material

### The AI default

Cards have shadows. Buttons have shadows. The hero has a shadow
under the CTA. The page reads as "elevated" because everything
is `box-shadow`. The shadow is the only material in the system;
without it, every element is flat, identical-weight.

### The principle

Material is **light and shadow on a surface**. Most 2026 web
pages do not need shadows; they need **hairline borders**,
**subtle texture**, and **negative space**. A hairline border
on a 1px line of `--c-line` is more designed than a
`box-shadow: 0 8px 24px rgba(0,0,0,.15)`. A subtle paper-grain
texture on a `--c-bg-elev` surface is more designed than a
drop-shadow card.

A few specific moves that earn their place:

- **Hairline border** (`border: 1px solid var(--c-line)`) instead
  of shadow, for cards and dividers.
- **Paper grain** (a subtle SVG noise filter at 2-4% opacity) on
  a dark canvas. Adds depth without weight.
- **A printed-canvas feel** (a hand-drawn texture overlay, very
  subtle) for editorial sections.
- **A flat surface** (no shadow, no border) when the content
  itself is the design.

### Specificity test

- Does every card have a shadow? (If yes, the material is
  uniform. If no, the cards are differentiated by content, not
  by chrome.)
- Is there at least one surface on the page that uses a hairline
  border instead of a shadow?
- Is there at least one surface with a subtle texture (grain,
  paper, noise) — or is everything flat?

## 6. Voice in copy

### The AI default

"Welcome to our shop. We offer a wide range of high-quality
products made with care. Our team is dedicated to providing the
best experience for our customers." This is the AI default: vague
claims, no specifics, no numbers, no names, no places. It reads
as filler because it is filler.

### The principle

Specificity is the test. Every claim has a number, a name, a
place, or a date. The copy sounds like a person wrote it because
a person did, and a person only writes specifics.

Examples of AI-default copy and the specificity-tested version:

| AI default | Specificity-tested |
|---|---|
| "Hand-poured candles" | "Hand-poured in our back room since opening day. 7 years, three wicks, same recipe." |
| "Locally-roasted coffee" | "Roasted Tuesday and Friday at Limestone Coffee, 14 miles east of us. Picked up the morning of delivery." |
| "Quality ingredients" | "Castile bar soap, 5oz, hand-cut, 4-week cure. Olive and coconut oil, lye, water. That's it." |
| "Visit our store" | "115 East Stephen Foster Ave, on the square. M-Sa 9-6, Su 11-4. We're between the diner and the old pharmacy." |
| "Friendly staff" | "Sarah, who has worked the counter since 2018, will probably be the one to hand you your bag." |

### Specificity test

The 4-question test, applied to every paragraph:

1. Is there a number, a name, a place, or a date? (If not, the
   paragraph is AI default.)
2. Is there a verb that describes a real action? ("Poured,"
   "roasted," "split," "served" — not "provided," "delivered,"
   "ensured.")
3. Could a person reading this paragraph tell a friend one
   specific fact? (If not, the paragraph is too vague.)
4. Does it sound like a person wrote it, or like a press kit
   generated it?

## 7. Custom detail

### The AI default

Every icon is from a free library (Heroicons, Lucide). Every
illustration is a placeholder. The dividers are 1px lines. The
brand mark is a wordmark in a font. The page reads as "assembled
from a kit" because it was.

### The principle

A designed page has at least one *made* element — something that
a person drew, painted, typeset, photographed, coded, or
composed by hand. It does not have to be elaborate. It has to be
specific.

Candidates:

- A custom SVG of the storefront (a flat 3-color illustration
  drawn at 200x150)
- A hand-drawn map of the area with the shop marked
- A custom divider — an SVG of a leaf, a wave, a stitch, a
  motif specific to the merchant
- A real photograph of the merchant's product, with
  specific lighting and a specific angle
- A custom icon set for the merchant's categories (a candle
  flame, a coffee bean, a measuring cup — drawn to match)
- A custom letterform or wordmark in SVG, not a font

### Specificity test

- Is there at least one *made* element on the page? (Not
  from a library — made for this merchant.)
- If a reader looked at that element, would they know it was
  specific to this merchant? (If not, it is generic.)

## 8. The Specificity Test (one-page checklist)

Before any new design work ships, run the eight checks. A
passing design hits at least six of the eight. An A+ design
hits all eight.

| # | Check | Pass / Fail |
|---|---|---|
| 1 | **Asymmetric layout.** Dominant column + secondary column, not two equal halves. | |
| 2 | **Typographic depth.** Variable display font with `opsz`. Oldstyle numerals in running text. Real small caps on eyebrows. A 1.25+ modular scale. | |
| 3 | **Layout detail.** At least one drop cap. At least one margin note in a secondary column. At least one pull quote broken out. | |
| 4 | **Imagery with intent.** At least one specific image (not stock). At least one image-free section by design. At least one *made* element. | |
| 5 | **Material.** Not every card has a shadow. At least one hairline border. At least one subtle texture or flat-by-design surface. | |
| 6 | **Voice in copy.** Every paragraph has a number, a name, a place, or a date. Real verbs, not press-kit verbs. | |
| 7 | **Custom detail.** At least one *made* element on the page specific to this merchant. | |
| 8 | **Single-accent restraint.** (From the brand-wide language.) One accent color, three roles. | |

If any check is empty after the test, the design has regressed
to the AI default. Fix that check before shipping.

## 9. How this layers on the existing language

The brand-wide design language is the **floor** — it captures
restraint, the motion grammar, the section grammar, the button
system, the font pair, the single-accent rule. Every pattern in
this document assumes the floor is in place.

This document is the **ceiling** — it captures composition,
depth, voice, and custom detail. The level-up is not "different
rules." It is "more rules, applied with more intent."

The eight ship-able patterns in the brand-wide language
(`design-language-hero-pattern`, `design-language-section-grammar`,
etc.) become *more* themselves when the depth principles are
applied. The hero pattern becomes an asymmetric editorial
composition. The section grammar becomes a rhythm with
typographic depth. The menu card becomes a card with real
specifics and a real maker credit.

Nothing in this document overrides the brand-wide language. It
extends it. When in doubt, the brand-wide language wins on
restraint; this document wins on depth.

## 10. Anti-patterns (the AI tells)

These are the visual tells that a design was generated, not
designed. Each is paired with the depth-principle counter.

| Tell | Counter |
|---|---|
| Hero with abstract gradient mesh and centered text | Asymmetric hero with a real image, or no hero image at all |
| Three-column "Fast / Secure / Reliable" feature grid with identical cards | Editorial pitch with a pull quote; specific facts, not generic benefits |
| Lorem-ipsum body copy ("we are dedicated to", "we pride ourselves on") | Specificity-tested copy (numbers, names, places) |
| Every section is a 12-col grid with equal card weights | Mixed grid: dominant column + secondary column, varied card weights |
| System Inter / SF Pro everywhere, no display face | Variable display font with `opsz` axis, system sans for body |
| Centered everything — hero, nav, cards, footer | Left-aligned or asymmetric layout, with intentional alignment |
| Glassmorphism / frosted-glass cards | Hairline borders, subtle texture, flat surfaces |
| Stock-avatar social proof (circular avatars, fake names) | Real maker names, real places, real dates |
| Generic CTA copy ("Get started", "Learn more", "Sign up") | Specific CTA copy ("Read the menu", "Visit the shop", "Call Sarah") |
| Equal-weight everything (every heading is `h2 24px bold`) | Real hierarchy: one hero title that is largest, section titles that are clearly secondary |
| Floating geometric shapes for "depth" | Real depth via material, type, and image |
| Background gradient scrolls, animated meshes, particle systems | Flat background, real imagery, real type |

If a design hits more than three of these, it is generated, not
designed. If a design hits none, it is at the A+ bar.

## 11. Adoption path

This document is canonical. Use it like this:

- **Before starting a new design**, read this document and the
  brand-wide language. Both are loaded by the wiki auto-loader
  for any project work.
- **Before shipping a new design**, run the eight-point
  Specificity Test (§8). Hit at least six of eight. Hit all
  eight before calling the design A+.
- **When the brand-wide language is updated** (a new pattern
  ships, a new motion is added), check whether the depth
  principles in this document need a corresponding update. They
  usually do not — the depth principles are about composition,
  not about specific patterns.
- **When the depth principles here prove wrong** (a specific
  depth move does not hold up across tenants, or a counter
  becomes stronger than the principle), supersede with a new
  ADR in the cross-cluster decisions folder. Do not edit this
  document silently.

The Yard & Larder reference under `reference/` is the first
implementation of these principles. It is intentionally not a
template — it is a proof. New work that hits the same bar is
what the next generation of tenant forks should look like.
